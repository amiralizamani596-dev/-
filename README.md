# مدرسه‌یار (فرانت‌اند + بک‌اند نمونه)

پروژه مدیریت مدرسه با **React + Vite** (RTL، فارسی). حالت پیش‌فرض همچنان **فرانت‌اند/Mock** است (بدون نیاز به بک‌اند)، اما یک بک‌اند نمونه (Node/Express) اضافه شده و فرانت‌اند می‌تواند در حالت `api` به آن متصل شود. ساختار طوری نگه داشته شده که امکان برگشت به حالت قبلی ساده باشد.

## ساختار پروژه
- `src/` → فرانت‌اند (React + Vite)
- `server/` → بک‌اند نمونه (Express)
- `.env.example` → تنظیمات نمونه فرانت‌اند (`VITE_*`)

## پیش‌نیاز
- Node.js و npm
- روی ویندوز، اگر اجرای `npm` در PowerShell به خاطر Execution Policy خطا داد، از `cmd /c npm ...` استفاده کنید.

## اجرا (حالت پیش‌فرض Mock - بدون بک‌اند)
```powershell
# نصب وابستگی‌های فرانت‌اند (در صورت نیاز)
cmd /c npm install

# اجرای فرانت‌اند
cmd /c npm run dev
```

سپس آدرس نمایش‌داده‌شده توسط Vite (معمولاً `http://localhost:5173` یا پورت دیگر) را باز کنید.

## اجرای بک‌اند نمونه
```powershell
# نصب وابستگی‌های بک‌اند (یک‌بار)
cmd /c npm --prefix server install

# اجرای سرور
cmd /c npm --prefix server run start

# یا حالت توسعه (Node watch، اگر پشتیبانی شود)
cmd /c npm --prefix server run dev
```

- پیش‌فرض سرور: `http://localhost:3001`
- سلامت سرویس: `GET /api/health`
- ورود: `POST /api/auth/login` با بدنه JSON `{ "role": "student|teacher|admin", "username": "...", "password": "..." }`

## اتصال فرانت‌اند به بک‌اند (حالت API)
1. فایل `.env` در ریشه پروژه بسازید (یا `.env.example` را کپی کنید).
2. مقادیر را تنظیم کنید:
   ```env
   VITE_DATA_MODE=api
   # برای توسعه با Vite proxy خالی بگذارید (پیشنهادی)
   VITE_API_BASE_URL=
   ```
3. سرور بک‌اند را اجرا کنید (`http://localhost:3001`).
4. فرانت‌اند را اجرا/ری‌استارت کنید (`npm run dev`).

> در حالت توسعه، Vite مسیر `/api` را به `http://localhost:3001` پراکسی می‌کند (تنظیم در `vite.config.js`).  
> اگر بخواهید مستقیم به بک‌اند وصل شوید، می‌توانید `VITE_API_BASE_URL=http://localhost:3001` تنظیم کنید.

## نقش‌ها و ورود نمونه
- **دانش‌آموز:** `student` / `1234`
- **دبیر:** `teacher` / `1234`
- **مدیر:** `admin` / `1234`

این اطلاعات در هر دو بخش زیر هماهنگ نگه داشته شده‌اند:
- فرانت‌اند (Mock): `src/config/auth.js`
- بک‌اند نمونه: `server/index.js`

## قابلیت‌های پیاده‌سازی‌شده (خلاصه)
- لندینگ معرفی سامانه + بخش‌های امکانات، نقش‌ها، راه‌اندازی، امنیت، پرسش‌ها و راهنما
- جریان ورود جداگانه برای دانش‌آموز، مدیر و دبیر (صفحه انتخاب نقش «ورود مدیر یا دبیر»)
- پنل‌های نقش‌محور (دانش‌آموز/دبیر/مدیر) با داده‌های نمونه
- برنامه هفتگی با نمایش افقی در مودال
- مودال‌ها با بستن از طریق کلیک بیرون و کلید `Escape`
- بهبودهای UI/UX و ریسپانسیو
- حفظ وضعیت نشست در `sessionStorage` و همگام‌سازی view با hash آدرس
- عنوان صفحه (`document.title`) پویا بر اساس بخش/نقش
- لایه سرویس ورود با پشتیبانی `mock/api` (`src/services/session.js`)

## نکات مهم برای توسعه بک‌اند (قابل برگشت)
- **حالت پیش‌فرض `mock` است**؛ بدون تغییر env رفتار فعلی فرانت‌اند حفظ می‌شود.
- فراخوانی‌های احراز هویت در `src/services/session.js` متمرکز شده‌اند.
- تنظیم حالت اجرا و آدرس API در `src/config/app.js` و متغیرهای `VITE_*` انجام می‌شود.
- بک‌اند فعلی یک نمونه ابتدایی (احراز هویت دمو) است؛ برای تولید باید مواردی مثل ذخیره‌سازی واقعی، رمزنگاری/هش رمز، توکن/سشن امن، اعتبارسنجی کامل و مجوزها اضافه شود.

## برگشت به حالت قبلی (بدون بک‌اند / حالت فرانت‌اند فعلی)

### گزینه ۱: برگشت سریع (بدون حذف فایل‌ها)
- `VITE_DATA_MODE` را روی `mock` بگذارید (یا اصلاً تنظیم نکنید؛ پیش‌فرض `mock` است).
- سرور بک‌اند را اجرا نکنید.
- فرانت‌اند مانند قبل با داده/ورود نمونه کار می‌کند.

### گزینه ۲: بازگردانی کامل به وضعیت مبنای قبل از اضافه شدن بک‌اند
- یک بکاپ مبنا (بدون `node_modules`/`dist`) از وضعیت قبلی در این مسیر وجود دارد:
  - `C:\Users\comiran\Desktop\open-code-baseline-frontend`
- برای بازگشت کامل، محتوای پروژه فعلی را با این بکاپ جایگزین کنید (یا فایل‌های لازم را از آن برگردانید).

### گزینه ۳ (پیشنهاد، اگر Git نصب باشد)
- `git init`
- ثبت وضعیت فعلی به‌عنوان baseline (commit)
- ساخت شاخه جدا برای توسعه بک‌اند (مثلاً `backend`)
- انجام تغییرات بعدی روی شاخه جدا برای rollback آسان با checkout/revert
